# 版本记录

最新的在最前。各版本开头「打开 `Epson-Scan-plus-v0.4.x/…`」指作者本机的发布目录；0.3.1 及以前的名称是 Film Desk。

## 未发布 A7R IV 联机翻拍；翻拍和扫描用同一套去色罩

- **A7R IV 联机翻拍**（还没在真机上测过）：
  - **相机进程**：新的 `EpsonCameraHelper` 和扫描仪的采集进程一样，单独运行，通过 Sony Camera Remote SDK 2.02 驱动相机。构建时找到 SDK 才编进去，SDK 本身不进仓库。
  - **能做的**：连接、实时取景、点画面设对焦点、半按快门自动对焦、按 Near/Far 7/3/1 档步进对焦和拖对焦环、App 自己的精确对焦（按对焦框里的颗粒清晰度逐级逼近）、设置快门 / 光圈 / ISO / 对焦模式 / 文件格式 / 保存位置、拍摄并接收文件。
  - **看画面**：对焦检查按 100% / 200% / 400% 显示上一张照片的原始像素。
  - **入库**：照片进库里一卷「翻拍」的卷，RAW 解成线性 16 位 TIFF。像素位移按张数归组，合成还没做。
  - 自检增加 18 项，包括启动 App 里带的相机进程、确认 SDK 能从 App 里载入。
- **液态玻璃**（macOS 26 上）：
  - **拍摄区**：上下控制条和右边的对焦检查都是浮在取景画面上的玻璃。对焦点上有一个放大 4 倍的玻璃放大镜。
  - **快门**：圆形的玻璃快门键，快门动作时亮起一圈光；照片入库时浮出一条玻璃提示。
  - **库**：标题栏浮在档案柜上；鼠标停在透明袋里某一格上时，浮起一个玻璃放大镜。
  - **模块旋钮**：加了玻璃顶盖和高光，整个旋钮放在一块玻璃上。
  - 设置环境变量 `EPSON_SCAN_PLUS_NO_GLASS` 可以换回控制台外观，截图时用：离屏截图抓不到系统的玻璃。
- **会流动的液态玻璃**（用 Xcode 和 macOS 26 SDK 构建，在 macOS 26 上；还没在真屏上看过）：
  - **模块旋钮**：所在模块下有一滴琥珀色玻璃，转旋钮时流到下一个模块。
  - **顶栏**：按键都是玻璃。换模块时按位置流进下一个模块的按键，多出来的从旁边分出来，少了的并回去。
  - **按下会回弹**：快门键、AF、精确对焦、顶栏按键和主要按钮。
  - **快门**：「第 NN 张已入库」从快门键里长出来，往上浮，脱离成一滴。像素位移每收到一张亮一颗玻璃珠，收齐后合成一滴。
  - **画面延伸**：取景画面和去漏光的照片模糊地延伸到两侧面板下面。
  - **主要按钮**：「扫描所选」「下一步：去色罩」「开始去漏光」「导出」等是琥珀色玻璃。去漏光的对比拖柄是透明玻璃做的竖条。
  - 用 Command Line Tools 构建，或在旧系统上，保持原来的样子。
  - **用 Xcode 构建时扫描仪进程会崩溃，已修好**：macOS 27 SDK 里有 `pipe2`，libusb 的 configure 检测到后就弱链接了它；macOS 26 上没有这个函数，一初始化 USB 就崩溃，App 提示「48-bit 接口异常退出」。现在构建时关掉 `pipe2`，扫描仪的库里只要有弱链接的函数就不让构建通过。自检会启动 App 里带的扫描仪进程，确认它不崩溃。

- **第一晚实测 A7R IV 后的修正**：
  - **快门**：相机在 DMF 时，App 原来不先半按就直接全按，对焦优先的相机什么也不拍。现在 DMF 和其他 AF 模式都先半按到合焦再全按。按快门前，相机若没交出「电脑优先」就先要过来，并像 Sony 示例那样先半按一下。每一步的结果写进诊断信息；按了 10 秒没收到照片会提示。
  - **刚连上时的 0x8402**：意思是相机还没准备好，电脑优先、保存位置和第一次读设置现在会在 3 秒内重试。
  - **手动对焦**：不在 MF 时按步进或拖对焦环，先切到 MF 再走。
  - **对焦放大**：原来的 2× / 4× 只是放大 1024 像素的取景小图。现在用相机自己的对焦放大（5.9×、11.9×），取景就是对焦点附近的传感器像素；回到 1× 用相机的 ×1.0 档；倍数跟着相机报的值走；切换对焦模式后自动恢复放大。
  - **拍摄页不再发橙**：取景画面不再延伸到两侧面板下面，负片的橙色色罩原来会把整个窗口染橙。
  - **去掉红、绿、蓝滤色片**。
  - **库**：每页透明袋的阴影改成只按页面外框算，打开和浮起不再卡（离屏测量，画一遍从 2.5 秒到约 0.12 秒）。
- **接触表分页，点画面放大到中央**：
  - **预设标定：按去色罩原理挑点和去点**：
    - **原理**：中性的东西除掉片基以后，同一种光下从亮到暗落在一条直线上。挑点、去点都只按这一条，不和 C1 或别的渲染比颜色。
    - **MCP 的报告**：有点偏离 0.03 D 以上时，在所有 3 个以上的组合里（最多 12 个点）找彼此落在一条线上的最大一组，报告组外的点。两组各自一致、斜率差 0.03 以上时，点名分歧的点，请助手再加点，不再逐个去掉偏离最大的。
    - **给助手的说明**：
      - 所有点在同一种光下（阳光、或同一片阴影），中途调过灯的画面不要混；
      - 光谱平坦的材料；
      - 亮的、暗的各两样以上；
      - 加点前先 sample 确认。
    - 面板说明和 README 也去掉了「阴影里的灰」。自检增加 1 项。
  - **端到端验证（R22 的 17 个 ARW）**：
    - **路径**：RAW 按相机传照片的路径进卷，之后全部经过 App 的 `--mcp` 桥接进程和 socket：选预设、整卷自动裁切、预览、取样、加点、去点、生成预设。默认结果和从解好的 TIFF 算的一致。
    - **按原理取点**：只取阳光下、7488 以前的白墙、白石块、水泥地、人行道。报告给出两组：蓝 0.628 和 0.664，分歧在一处水泥地和一处人行道。再加阳光下的点也分不开，因为这卷里阳光下暗的中性东西太少。
    - **留出的中性点本身就差 ±0.05 D**（蓝），和两组的差别一样大。要定得更准，需要拍在胶片上的灰卡或灰阶。
    - **7488 以后的点都偏同一个方向**（蓝 +0.08 到 +0.14 D）。报告能把它们和前面的点分开。
  - **预设标定：标出中性点**：
    - **取点时**：单张画面上每个点一个白圈和编号「中性 1」「中性 2」……，手动取点和 AI 助手取点都一样。
    - **生成预设以后**：点在哪一张、哪个位置存进预设，那几张画面上照样标出。标定面板列出每个点在哪一张，点一下打开那一张；「标出」开关显示或隐藏。
    - **位置**：记在照片（或预览）上，改裁切、拉直以后标记照样落在原处。
    - `calibration_make_preset` 的回复会告诉用户去哪里看。自检增加 1 项。
  - **MCP 标定在 R22 上的实测**：
    - **怎么做的**：只看预览、按物体挑点，按工具报告的偏离去掉不中性的点。留下 7484 的白墙、7483 的水泥地、7479 的白石块，残差 0.015 D，蓝斜率 0.719。
    - **结果**：用在没取点的几张上，和 C1 的色差 7478 7.9 → 3.6，7493 8.0 → 4.1，中性处的 b* −13 → 0 附近。7491 5.4 → 7.0，原因还没查清。
    - **过程中按提示去掉的点**：
      - 7488 的柏油路（蓝偏 0.14 D）；
      - 7485 阴影里的柱子（受红地砖反光）；
      - 7478 的人行道和刷漆的铁箱；
      - 一个取偏到石块旁暗处的点：`sample` 读到几乎黑。
  - **翻拍：自动裁切**：
    - **入口**：单张视图「画面范围」里的「自动裁切」裁这一张；点箭头选「整卷自动裁切」整卷一起裁。AI 助手用 `auto_crop`。
    - **怎么找边**：沿每条边，找片基转入画面、变密的地方，取多数位置落在的那条直线为片框的边（斜 ±3° 以内，按它拉直）。裁在四条边以内，再收进短边的 0.5%。
    - **整卷对照**：一卷的画面大小差不多。哪张的一条边离整卷的画面大小差 2% 以上，就把离它平常位置更远的那条边，按另一条边和整卷的大小改正。没找到的边也这样补，补出来落在照片外的，就裁在照片的边上。
    - **结果**：就是普通的裁切和拉直，一步撤销，原文件不改。
    - **和 C1 的手动裁切比**（R22 的 17 张）：中心差 0.35% 以内，大小小 0–0.9%；C1 里拉直过的 5 张，方向一致，角度差 0.11° 以内。整卷对照以前，7483、7484 底部有一大片和片基一样淡的阴影，被当成了片框的边，裁掉了画面的 10%–15%；对照以后改正了。
    - 自检增加 5 项。
  - **翻拍：让 AI 助手做翻拍标定（MCP）**：
    - **新工具**：`calibration_add_points`、`calibration_state`、`calibration_remove_point`、`calibration_clear`、`calibration_make_preset`。
    - **取点**：在选中画面上加中性点，取浮点读数、7×7 平均。原来的 8 位读法在线性负片密的地方误差有几个百分点。
    - **报告**：返回每个点高于片基的密度、目前的拟合（斜率、残差、趾部），以及每个点偏离拟合多少。拟合不到一起时，会说去掉哪一个以后就可以。
    - **生成预设**：翻拍的卷生成「胶片 · 翻拍」，扫描的卷生成「· V850」。
    - **MCP 说明里写了怎么挑点**：
      - 按物体判断，不按颜色判断；
      - 优先用拍在胶片上的色卡灰块，其次是白或灰的牌子、墙、水泥、柏油路、阴天的云、雪；
      - 避开天空、植物、皮肤、木头、有颜色的墙、夕阳或灯光下的东西、溢出的白和最暗处；
      - 亮、中、暗都要有，共 3–6 个；偏离 0.03 D 以上的点去掉；
      - 看预览时，画面会发给 AI 服务。
    - 自检增加 3 项。
  - **翻拍：光源标定（串色矩阵和平场）**：
    - **为什么**：
      - 串色矩阵原来是 10-29 用 IT8 测的一次，那次曝光暗了 2–3 档，没法按会话重测。
      - 翻拍灯在画面四周偏暗：IT8 那次角上和中间差约 0.1 D，片边测到的片基也常比画面中间最薄的片子还暗。四周因此密度偏高、发暗，各灯衰减不一样时还会偏色。
    - **怎么做**：翻拍页左栏有「光源标定」。拿走底片，只开红灯、只开绿灯、只开蓝灯各拍一张空白帧，点「用最近三张标定光源」，三张顺序不限。
      - **矩阵**：每种灯在三个通道里的比例，取曝光在 5–95% 之间那些像素的中位数。
      - **平场**：去串色后每种灯自己的通道，按 24 × 16 格取中位数，再除以最亮的一格；灯几乎照不到的格子不动。
      - **结果**：存在本机设置里，状态栏报出最大的那项串色、四角各种灯有多暗；曝光不够时会提示重拍。
    - **读图**：读出 RAW，先乘矩阵的逆去串色，再除以平场（格子之间线性插值），之后才测片基、密度和白平衡。去串色以后每个通道只剩一种灯的光，所以每种灯按它自己的衰减补平，是准确的。
    - **开关和换算**：
      - 「去串色」开关在有了标定以后变成「去串色和平场」，整卷一起开关，⌘Z 撤销。
      - 取过的读数按顺序换算：先按旧平场还原，再换串色，再按新平场。手动取的片基按取的位置换算；中性灰、高光和整卷片基没有记位置，按画面中间换算。
      - 片边片基重新测一遍。
      - 新拍的照片跟着这一卷；一卷的第一张跟着最近一次标定。标定完，当前这一卷也换成新的。
    - **验证**：
      - 合成的三张空白帧（已知矩阵；每种灯从偏离中心的一点、按不同幅度衰减）：矩阵误差在 0.01 内，四角的平场和造的完全一样。
      - 一张被灯照得不匀的片基（四角和中间差 57%），校正后差别在 1% 以内。
      - 拿 10-29 那三张单色 IT8 翻拍做矩阵，和当时的 IT8 分析每一项相差都不到 0.006（蓝灯漏进绿：0.330，当时 0.336）。那三张里有色卡，所以它们的平场不作数。
    - **修过的问题**：Core Image 把位图的第一行当顶边，原来多翻了一次，平场上下颠倒了。自检里的衰减中心改成上下也偏，就是为了抓这种错误。
    - **没做**：杂光扣除。它要再拍一张中间挡不透光黑片的帧，先不做。
    - 自检增加 6 项。
  - **更「油润」：色彩降噪、暗部保色、柔和的两头**（对照 C1，见 `油润-2026-10-30/比较.md`）：
    - **比较的结果**：C1 比 App 油润在三处。
      - 暗部和中间调颜色足：App 默认在 L* 35 以下只有 C1 的 0.5–0.86。
      - 两头柔：C1 最暗 5% 在 L* 3、最亮 5% 在 71，App 是 1 和 76。
      - 顺滑：App 的蓝黄色噪声多 66%、明度噪声多 23%。C1 用了默认降噪 50/50/50，曲线是 Linear Response，也没有加饱和度。
    - **色彩降噪**：在转换后，把每个像素的颜色和亮度（luma）分开，只把颜色做高斯平滑，再和原来的亮度合回去，亮度一点不变。
      - 半径按画面大小算：全分辨率 9600 像素时约 2 像素，缩小的预览按比例减弱。
      - 翻拍的照片入库时设为 1，旧卷打开时补上；重置调整也保留它。扫描默认关。
      - 在 R22-7478 全分辨率（缩到 3000 像素比较）上：平坦中间调的色噪 a* 2.95 → 1.60、b* 3.99 → 2.10，比 C1（2.90 / 2.40）还低；明度噪声和细节基本不变（1.25 → 1.21，8.83 → 8.78），颗粒保留。
    - **柔和的暗部和高光**（`softEnds`，默认开，关掉回到直切）：
      - **暗部**：输出值 0.05 以下改成指数趾部，自动色阶的最暗 0.5% 不再切成纯黑，各通道的差别和颜色留着。
      - **高光**：0.9 以上用指数肩部收向白。
      - **暗部饱和度**：最多补 30%，越亮补得越少。
      - **怎么定的参数**：在 R22 三张、翻拍标定后，对照 C1 在 3×3×3 的组合里选。L* 50 以下的彩度比从 0.63 / 0.80 / 0.86 升到 0.74 / 0.93 / 0.95，近白处彩度从 1.02 降到 0.92（C1 的白更干净）。整体色差基本不变（5.91 → 5.95）。补 60% 的暗部饱和度会让中间调超过 C1，肩部从 0.75、0.82 开始会把高光压灰。
      - **修了一个溢出**：两段曲线各自只在自己那一侧计算 exp。不然片夹这种极密的地方会算出无穷，被 `mix` 变成 NaN，接触表上的片夹就成了黑的。
    - 自检增加 3 项，改写 1 项（−1 EV 找回高光那一项，现在用直切测）。
  - **翻拍：用中性点标定翻拍预设**：
    - **为什么**：翻拍卷的整卷估计，在 R22 上蓝斜率低约 18%。应该中性的地方（白牌子、水泥）b* 是 −12 到 −16，越亮越蓝。原因是蓝层的反差随密度一直在变，而估计取整卷所有明暗过渡的中位数，落在哪一段取决于画面内容（树叶多就落在低处）。去掉趾部、只用最灰的边、取众数、从边拟合趾部宽度都试过，都不行，详见 `蓝斜率-2026-10-30/结论.md`。
    - **现在**：卷是翻拍的时，「本机预设标定」变成「翻拍预设标定」，按钮是「生成翻拍预设」。
      - 预设名是「胶片 · 翻拍」，id 带 `-copy-`，出处写「翻拍标定 · 相机型号」。
      - 同一种胶片的翻拍卷自动用它，扫描的卷不会用；扫描的「· V850」预设也只给扫描的卷。
      - 说明里写清楚：标定的是每个通道的反差；白平衡照旧自动或自己定，胶片的风格保留。
      - 「转换依据」在翻拍卷上提示整卷估计会随画面内容偏，建议标定。有了标定以后，整卷估计和预设对不上时，翻拍卷上不再提示「可能是胶片不同」。
    - **效果**：在 R22-7478 上取 3 个中性点（L* 约 35、55、75 的灰）生成「Kodak Ektar 100 · 翻拍」，斜率 R 0.458 · B 0.717，整卷估计是 0.427 · 0.591。
      - 7478、7493 上应中性的地方回到 b* +0.6 和 −1.8，和 C1 的色差从 8.1 降到 4.6 和 3.7。
      - 7491 变差（8.3，偏绿）：它是调过灯以后拍的。按理去串色以后配比不影响，没变好的原因还没查。
    - 串色矩阵保留：去串色在读图时先做，标定在它后面只改斜率。预设说明如实记录标定时去串色是开着、关着，还是点里两种都有，原来一律写「开着」。
    - 自检增加 2 项。
  - **翻拍：片基自动从片边取，标出取的地方**：
    - **为什么**：翻拍的照片里没有扫描那样的片间可测，原来不手动取片基时，就用每张最薄的地方代替。那往往是画面里的暗部，颜色可能差很远：R21-6436 那里是 R/G 0.47、B/G 0.45，真正的片基是 0.38 / 0.62。
    - **怎么找**：在照片四边先找画框的边，即由外往里第一条「再往里就密 0.05 D 以上」、这一边三成以上都成立的直线，外面是削波空光的跳过。只在线外面取：排除空光和它周围 3 像素，留下沿边均匀、颜色最多、最亮 8% 的那部分，整行或整列三成以上是它，并且连着照片边缘。
      - 最早只按亮度和颜色找，把画面里很暗的阴影也取进来了（R22-7478 左边的草地）。阴影和片基只差 0.03 D 以内，只有画框线分得开。
    - **每张用自己的**：翻拍时可能中途调过灯，R22 里就有两种片基颜色，所以每张用自己的；看不到片边的用最近一张看得到的。一卷里三张以上测到时，颜色谁都不像的那张不采用（R12-7830 就是，很可能是片夹）。手动取的片基、整卷共用的片基照旧优先。
    - **结果**：C1 目录里 RGB 光源的卷和 App 自己的三卷，共 104 张，85 张找到了片边片基。同一卷里颜色一致：每张和整卷中位数的差别，典型是 0.3–0.7%；R22 中途调过灯，是 1.2%。每张约 0.15 秒，在后台做，结果存在工程里。
    - **标出**：调整面板写明片基来自哪里（这一张的片边、第几张的片边、手动、整卷共用、最薄处）。打开「标出」后，单张上用琥珀色标出取片基的地方；手动取的片基画成一个圈，位置跟着撤销。用「取片基」工具时，自动找到的片基也标出来。MCP 的 get_state 也报片边来源。
    - **对和 C1 比的分数**：开着自动白平衡时几乎不变，因为它会在暗部重新对齐三个通道（见 `蓝斜率-2026-10-30` 的检查）。片基对了，关掉自动白平衡、取中性点或标定时才有意义。
    - 自检增加 8 项：片边找片基、不取画面里的阴影（包括伸到片间的）、裁到画框里找不到、每张自己的、最近一张的、颜色孤立的不用、手动取的位置和撤销、整卷共用优先。
  - **翻拍：去掉 RGB 光源的串色**：
    - 从传感器读出的翻拍照片（无压缩 ARW），在线性读数上、除片基之前，乘串色矩阵的逆。矩阵是 2026-10-29 用 IT8 色卡分别只开红、绿、蓝灯翻拍测出的：蓝灯 34% 读进绿，绿灯 12% 和 11% 读进红、蓝。
    - 做在读图那一步（和扫描仪的杂光扣除同一处），所以片基、整卷斜率、白平衡、MCP 取样、看片镜和导出都看到去掉串色后的读数。原文件不改。
    - 去色罩 · 胶片里的「去串色 · RGB 光源」按整卷开关，⌘Z 撤销；取过的片基、中性灰和高光按同一矩阵换算。新拍的照片跟着这一卷；新的一卷沿用上次的选择，默认打开。

    - 和 C1 比：13 卷 55 张 RGB 光源画面，在饱和度 1.0 时彩度从约 0.75 升到接近 1。但中间调偏蓝也更明显。整卷斜率估计不变时，色差反而变大；每卷取最好的红、蓝斜率时，R22（7478、7491、7493）从 5.7 降到 4.3，R15 从 5.5 降到 4.4，有几卷变差，平均从 10.9 到 11.8。下一步是整卷估计的蓝斜率。
    - 自检增加 6 项：矩阵求逆、读数换算、认出传感器读的 TIFF、入库时去串色、关掉后片基跟着换算、撤销。
  - **翻拍：胶片条里能删照片，去掉精确对焦，取景上不放看片镜**：
    - **删除照片**：翻拍时胶片条右端有「删除」，删掉当前这张；右键胶片条里的任一张也能「删除这张」（各页都有，去漏光页除外）。删除后选中它后面的一张，删的是最后一张就选前一张；原来总是跳回第一张。⌘Z 撤销，原文件留在这一卷的文件夹里。翻拍页没有画布接 ⌫ 键，也不加 ⌫ 快捷键，免得在右栏写备注时删掉照片。
    - **去掉「精确对焦」**：按钮和 App 自己按清晰度一档档找焦点的功能都去掉了。对焦用 AF 锁焦，再步进微调。取景上方和对焦检查里的清晰度读数保留。
    - **取景画面上默认不放看片镜，开关也藏起来**：对焦看相机自己的对焦放大。代码留着，`CameraStage.loupeKey` 改成 true 就能恢复开关。
  - **一张一个文件的画面排成接触表**：翻拍和导入的画面像冲印的接触表一样排在灯箱上，每条 6 张、每页 6 条。排满 36 张后下一页在右边：在灯箱上左右滑动，或用下方的「‹ 第 N / M 页 ›」翻页，整页推过去（打开「减弱动态效果」时淡入淡出）。选中别页的画面会翻到那一页。扫描的卷仍是片夹的整幅预览，另外导入的单张排在后面几页。原来翻拍卷的灯箱上只放所选的一张。
  - **修正：胶片条又会跟着所选的一张滚动**（夜间核对）：7dc145e 给滚动加了动画之后，单张里换张时胶片条就不再滚到所选的一张。原因是这条横向胶片条里，带动画的 scrollTo 一点都不动，换个时机调用也一样。现在改回直接滚过去，不做动画。离屏截图确认：选第 30 张后，它在胶片条中间、带高亮。
  - **液态玻璃动画**（夜间优化，macOS 26 上）：
    - 锁焦时，琥珀色的「已锁焦」小水滴从 AF 键里冒出来，松开时退回去。AF 键本身不再改字。
    - 拍摄页上方的直方图条挪到它的开关旁边，打开时从开关里流出来，收起时流回去。
    - 灯箱下方的「‹ 第 N / M 页 ›」从「N 个画面」旁边长出来；切接触表和单张时，下方工具条跟着平滑变化。灯箱上浮条的玻璃画法没改（浅色是磨砂，深色是系统玻璃），它们不能做液态玻璃的变形，只做了位置和大小的动画。
  - **翻拍时界面不挡画面**（夜间优化）：
    - 取景画面放在上下两排工具条之间，按钮、对焦环和快门都不压在画面上，胶片边缘能看全，翻拍时好摆正。1440 宽的窗口里画面小了约 14%。

  - **翻拍：相机连不上时说出是谁占着它**（另一个会话「相机连接被拒绝」做的）：
    - **原因**：Capture One、Lightroom 等通过 macOS 的图像捕捉（ptpcamerad）在相机一接上就接管它，Sony SDK 的连接被拒（0x8210）。
    - **现在**：找不到相机或连接被拒时，App 列出正开着的这类程序（Capture One、Lightroom、Lightroom Classic、照片、图像捕捉、Imaging Edge Remote），提示 ⌘Q 退出、相机关机再开。只有一个时说「退出它」。模拟相机加了 refuse=1，自检加 3 项。
  - **翻拍：锁焦后步进微调，快门不再对焦**（真机实测通过，2026-10-30 凌晨）：
    - **做法**：从 Capture One 的日志里看到，它在 DMF 里对完焦、半按还按着时，发 Near/Far 步进，相机收下并转动镜头。照着改：相机不提供 MF 时，AF 在 DMF 里半按到合焦并一直按住。焦点就此锁住，可以步进微调、精确对焦；全按时不再对焦。
    - **真机结果**：锁焦后 ±1 微调；连续两步 −3 清晰度 1481 → 1420，再 +3 回到 1490；拍摄前后清晰度 1490 → 1499，照片 2.5 秒到达。拍完一张相机自己松开半按，之后的步进提示「先按 AF」。再按 AF、再拍，第二张也到了。
    - **限制**：半按按住时相机不收任何设置，所以改设置前会先松开、解除锁焦并提示。镜头开关拨到 MF 时，相机驱动不了镜头：步进和 AF 都用不了，但焦点停在原处，快门不对焦。步进最大 6 档（相机报 7，Capture One 最多发 6）。
    - **App**：AF 键锁焦后显示「已锁焦」；精确对焦在没锁焦时先按 AF 再搜索。不再在自己这边先记下「已切到 MF」。模拟相机加了「镜头开关在 MF」和 DMF 锁焦的行为。自检增加 4 项，改写 4 项。
  - **翻拍：真机实测，找到快门又对焦、手动对焦用不了的原因**（2026-10-30 凌晨，A7R IV + Sigma 70mm 微距）：
    - 相机此时只提供 AF-S、AF-A、AF-C、DMF 四种对焦模式，没有 MF。镜头上的 AF / MF 开关在 AF 时就是这样。所以 App 或任何程序要切到 MF，相机都收下却不动。不在 MF 时，快门前的半按必然再对焦，对焦步进也被拒绝（0x60003）。
    - 「关掉半按对焦」（AFWithShutter）和「按一下对焦」（PushAutoFocus）这台相机不支持远程设置（0x8402）。
    - 相机在它提供的模式之间切换会生效，但要一秒多才变；半按按住时，任何设置都不收（0x8402）。
    - 照着这些改了相机进程：相机不提供的对焦模式不再去要（原来每次 AF、步进、快门都要重试好几秒，半按时近 20 秒），提供的写一次、读回两秒。AF 回报相机不提供 MF 时，App 说明快门会再对焦、步进用不了，请把镜头开关拨到 MF，用「精确对焦」。模拟相机加了「镜头开关在 AF」，自检增加 1 项。
    - 测试时三次拍摄都没有收到照片：当时相机在 AF 模式，焦点没有锁住，对焦优先不放快门。锁焦或镜头在 MF 时照片都正常到达。
  - **翻拍：对过焦后快门不再对焦，手动对焦可用**：
    - **原因**：AF 后 App 先在自己这边记下「已切到 MF」，相机进程在松开半按后马上切 MF，不重试也不确认。相机这时还忙，切换没生效，只写进了日志。之后 App 以为在 MF，快门前的半按就让相机又对了一次焦；对焦步进也一样，被拒绝或没动。另外对焦步进前从不要「电脑优先」：拧过转盘后，相机收下步进却不动镜头。
    - **现在**：AF、对焦步进和快门前，相机进程都先要「电脑优先」，再读相机报的对焦模式。不是 MF 就切过去，忙就重试，每次读回确认。AF 和快门回报是否真的在 MF，切不过去时 App 提示去看镜头上的 AF / MF 开关。
    - **模拟相机**：加了「刚松开半按时切对焦模式不生效」和「相机优先时步进不动镜头」两种行为；每次半按对焦、每一步都记下来。自检增加 2 项，改写 1 项。

- **翻拍实时取景上的放大镜换成看片镜**：和灯箱上同一个看片镜（型号在「显示」菜单里选），立在对焦点上；放大倍数不超过取景小图的像素能撑起的程度，要看传感器像素用相机自己的对焦放大。
- **全分辨率小块和看片镜不再反复重算**：用来判断「是不是同一张、同样设置」的键原来每次编码顺序可能不同，同一张画面会被当成变了，放大的那块可能一直出不来，看片镜一直重新渲染。
- **画面生成进度**：画布右上角的进度条，写着正在做哪一步（读取原图、分析片基白平衡色阶、冲印正片、直方图）；很快就完成的不显示。
- **拖滑块即时变化**：渲染用的原图读一次就留在内存里，原来每动一下都要重读一遍（翻拍的 TIFF 约 300 MB，每次 0.3–1.4 秒）；现在每一步约 0.1 秒。
- **看片镜**：新增 Peak 8×（135，看整张）和 Schneider-Kreuznach 10×（看局部对焦和颗粒）；3× 只留 Rodenstock。两种新型号的外形尺寸厂家没有公布，按照片估。
  - **单张里按胶片比例**：看片镜和画面一起按胶片的实际比例放大，像把灯箱连同看片镜一起凑近看（最大到画布能放下）。
  - **镜片下更清楚**：单张里只按全分辨率渲染镜片下面那一块（6000 万像素的画面整张渲染要几十秒，那一块不到一秒）；灯箱上按镜片实际需要的像素渲染这一张，从 2400 到 8192 像素，原来固定 2400，一张单独的照片放大 5.5 倍就糊了。
- **翻拍的 RAW 直接读传感器**：无压缩 ARW 不再经过系统的 RAW 引擎，不套相机的色彩矩阵和白平衡。每个感光点保留它测到的颜色（减去黑电平 512、按白电平 16383 归一），另外两种颜色用 Malvar–He–Cutler 梯度校正线性插值补出，输出传感器全尺寸 9600 × 6376、16 位线性。三个通道就是红、绿、蓝光各自的读数，适合 RGB 光源翻拍。A7R IV 的一张约 0.3 秒。压缩的 ARW 和其他 RAW 照旧交给系统引擎。
- **单张放大到像素**：放大超过当前那张图的分辨率时，看得到的部分按这张画面的全分辨率重新渲染（颜色用整张的片基、白平衡和色阶），平移后约一秒换上新的部分；每个图像像素占屏幕两个像素以上时不平滑，像素就是一格。最大放大从 8× 提到 32×。
- **扫描预览按灯箱方向**：边扫边显示的预览跟正式预览一样横排，看片镜在扫描中也能用。

- **全分辨率导出快了约 20 倍**：
  - **原因**：全分辨率原图原来是边画边从文件里读的，Core Image 每渲染一块就重读一遍。一张 6000 万像素的翻拍，分析要 11 秒，渲染加写文件又要 11 秒。
  - **现在**：先把原图完整解码进内存一次（约 0.2 秒），再分析和渲染。导出一张 16 位 TIFF 从约 27 秒降到约 1.4 秒；Adobe RGB 约 1.9 秒，JPEG 约 1.2 秒。单张放大到像素的那一块、看片镜的全分辨率也从同一份解码读，同样变快。
  - **连续导出不再越来越占内存**：每张导完就释放它的图像。原来要等整批导完才释放，6 张时内存升到 4.3 GB；现在稳定在约 2 GB，连导 6 张约 6 秒。
  - 代价是导出时内存峰值从约 1.4 GB 升到约 1.9 GB（一张 6000 万像素的翻拍）。
- **翻拍 RAW 的假色更少**：无压缩 ARW 的去马赛克从 Malvar–He–Cutler 线性滤波换成沿边缘插值：
  - **绿色**：按 Hamilton–Adams 的方法，从变化小的方向插值，两个方向按各自的平坦程度加权。
  - **红和蓝**：按它们和绿色的差值插值。差值在边缘两侧变化很慢，颜色本身变化却很大，所以不容易出假色。
  - **对比**：在已知答案的同心圆测试图上，色差误差低了 3.6 dB；真实画面缩小一半、做成马赛克再还原，误差持平或略好（伽马空间 PSNR 高 0.8 dB）；6100 万像素仍约 0.2 秒。对比图在 `outputs/去马赛克对比-2026-10-29/`。
  - **说明**：RawTherapee 的 RCD 是 GPL 代码，没有搬过来，是按公开的方法自己写的。

## 0.4.9 扫描对齐到预览、按行合并扫描、横排灯箱、扫描头、看片镜的位置、全卷旋转镜像、工具快捷键与更安全的取点

- **每张正式扫描对齐到预览**：实测发现 V850 每次扫描都自己校准读数——正式扫描的蓝色比 600 dpi 预览高约 11.5%，红色黑电平差 120–290 级；而片基和整卷估计是在预览上测的，所以正式扫描和它们不在同一个标尺上（以往由自动白平衡和本机预设的偏移抵消）。现在每张正式扫描到达时，和预览里同一块逐像素配准：先找到亚像素位置（三个通道一起判断），再在平滑处按通道拟合「扫描 = 增益 × 预览 + 偏移」，记入工程；转换、导出、缩略图、整卷估计都换算到预览的标尺读取，原始文件不改动。

  - **趾部模型**：D = Dmin + 斜率 · w · ln(1 + e^(x / w))，转换时求逆；在片基附近封顶，不放大颗粒。只有测得了片基（片间测量或手动取片基）时才使用，因为从画面自身推测的片基已经在趾部上。
  - **数据表的趾部不直接用于转换**：在 V850 扫描的同一卷 Portra 160（两次独立扫描、三段子集一致）上，按局部明暗过渡测得红、绿梯度比在片基附近从约 0.78 降到 0.68，与数据表大致相符；蓝、绿比却在 0–0.7 D 之间从约 1.0 一直升到 1.35，与数据表（约 1.2–1.3、近乎不变）不符。直接按数据表还原时，暗部打开了，但整张偏粉、发灰。所以默认转换仍是直线，与 0.4.7 相同。
  - **由本机标定测出趾部**：本机预设标定的中性点达到 4 个以上、其中有绿色密度低于 0.25 D 的很暗的点时（例如灰卡欠曝 2–3 档的包围），会同时拟合红、蓝的趾部宽度（绿色沿用数据表），生成的预设按它们还原暗部。合成测试中，5 个中性点准确还原了斜率和趾部（R 0.50 / 0.22、B 0.66 / 0.30）；用这样的趾部转换，灰阶保持中性（偏色 1 级，直线为 26 级），暗部层次从 29 级拉开到 43 级。中性点不够暗时照旧按直线标定。

## 0.4.4 设置、接触表、锐化与胶片预设标定

打开 `Epson-Scan-plus-v0.4.4/Epson Scan plus.app`，或解压 `Epson-Scan-plus-0.4.4-macOS-arm64.zip`。旧版本保留在各自目录，不被覆盖；请先退出旧版，不要同时运行两个版本。

本版改动了色彩处理：胶片预设、曝光、浮点统计和整卷片基都会改变，已有工程打开后颜色可能与 0.4.3 不同，原始扫描文件不受影响。以下功能尚未在扫描仪上实机复测：以 1200 dpi 扫描后生成接触表、对真实 48-bit 扫描的锐化，以及用真实灰卡标定预设。

- **胶片预设现在真正生效**：此前开启自动白平衡（默认）时，各通道按画面反差重新拉伸，抵消了预设的通道斜率。Portra 160、Portra 400、Ektar 100 的结果与「通用」逐像素相同。现在选择具体胶片时，通道反差按预设斜率决定，自动白平衡只对齐各通道黑点；「通用」仍按画面拉伸，可以自动修正颜色交叉。
  - **影响**：使用具体胶片预设的已有工程（默认是 Portra 160）颜色会变化。
  - **建议**：若负片与预设差异较大，暗部或亮部出现偏色时，改用「通用」，或用「选取中性灰」。
- **曝光改为印放曝光**：曝光原先是在裁切和中间调之后把显示值乘以 2^EV，+EV 会直接冲掉高光，−EV 也找不回已裁掉的高光。现在按每档 0.301 平移密度，在色阶与裁切之前生效。曝光为 0 的工程结果不变。
- **调整面板重新分组**：「色阶」只放自动、黑点、白点、中间调；曝光和对比度移到「影调」，饱和度移到「色彩」。
- **接触表视图可切换原片 / 反相**，默认反相：每张按各自的调色显示为正片，片边与片夹按本卷片基反相，看起来像一张接触印样。
- **设置（`⌘,`）**：
  - **扫描存储位置**：新的预览和导入会在此新建工程文件夹，已有工程不移动。
  - **默认导出格式**：TIFF 16-bit / TIFF 8-bit / JPEG / PNG 16-bit，可调 JPEG 质量。导出对话框中也能临时更换格式，命令行 `--format` 同样支持这四种。
  - **接触表排列**：胶片条或网格、每条 / 每行张数、白色相纸或黑底、是否按每张旋转、片号与标题。
- **导出接触表（`⌥⌘E`）**：把勾选画面排成一张 1200 dpi 的图片。
  - 尚未扫描或低于 1200 dpi 的画面先以 1200 dpi 扫描，结果保存为这些画面的原始文件；已有更高分辨率的扫描直接使用。
  - 先选好保存位置再开始扫描；取消或扫描失败时不生成接触表。
  - 扫描仪未就绪时，可选择用低清预览生成。
- **去色罩精度**（按调研的第一优先级）：
  - **浮点统计**：自动色彩统计和片基、中性点取样改用浮点数据。此前在 8-bit 数据上计算，线性扫描中负片的高密区只剩个位数的码值，片基、黑白端点和中性点都会被量化。
  - **按密度排除**：原先固定排除各通道都低于 0.025 的像素，在线性扫描里会把负片最密的高光整片丢掉，导致高光被裁切。现在只排除在每个通道上都比片基密 3.0 D 以上的近乎不透光区域，例如片夹和画框线。
  - **整卷片基**：从总览扫描中相邻画面之间的未曝光片基读取，供整卷共享，不再用每张画面里最薄的景物估计，因此高调画面也不会把片基估得偏密。手动「取片基」仍然优先。
  - **何时使用整卷片基**：只用于本程序的 48-bit 预览，以及画面裁自同一导入胶片条的情况；片间不干净或找不到间隙时，回退到逐张估计。调整面板会注明当前片基来自哪里。
  - **影响**：线性 48-bit 扫描的已有工程，颜色和高光会有变化。
- **本机胶片预设标定**（按 RawTherapee 的中性点反解）：
  - **原理**：中性物体在三个通道上的 log 曝光相同，所以每个通道的密度都可以写成「斜率 × 曝光 + 偏移」。以绿色为基准，绿色斜率沿用起始预设，由明暗不同的中性点反解红、蓝通道的斜率与中性偏移。2 个点时精确求解；3 个点以上用最小二乘拟合，并检查一致性。
  - **用法**：先在「预设」中选好胶片。在左侧「胶片 → 本机预设标定」点「取中性点」，在单张中依次点选中性灰；可以跨画面、跨卷。然后点「生成 V850 预设」。新预设名为「胶片名 · V850」，自动应用到当前工程，并保存在本机设置中；可在「设置 → 胶片预设」导出 JSON 或删除。
  - **斜率**：决定各通道反差，开启自动白平衡时同样生效。
  - **中性偏移**：在关闭自动白平衡、且没有手动中性点时，按标定结果配平。
  - **会拒绝的情况**：少于 2 个点；绿色密度跨度不足 0.3 D；解出的斜率超出 0.1–2.0；3 个点以上时拟合残差超过 0.08 D，通常说明有的点不是中性灰。
  - **验证**：合成数据上，2 个或 3 个点都能精确还原斜率与偏移；±0.01 D 噪声下斜率误差约 1.5%；混入一个偏色点会被拒绝。同一条中性灰阶在关闭自动白平衡时，标定预设的偏色为 0.0 级，数据表预设为 30 级。
  - **需要怎样的画面**：
    - **最好**：拍一张灰卡（18% 中灰，或白卡、灰卡、黑卡的组合），在同一卷上用 −2、0、+2 档包围曝光，日光下拍摄，与胶片的色温匹配。
    - **其次**：带灰阶的色卡（例如 ColorChecker 底排的六个灰块），或画面里确定是中性的大面积物体，例如白墙、灰色水泥、阴天天空下的灰色路面。
    - **取点**：落在均匀处，避开高光溢出、几乎透明的阴影趾部和反光。各点至少相差 1 档，绿色密度 0.3 D；最好覆盖 2 档以上。
    - **条件**：与要转换的胶片同一型号、同一冲洗方式，用这台 V850、同一片夹扫描。不同胶片型号要分别标定；同一型号的不同卷片基各不相同，由整卷片基分别处理，预设可以通用。
- **按实测 MTF 锐化**：
  - **建立配置**：在「设置 → 锐化」导入一张分辨率标靶的扫描（需带实心方块，例如 USAF 1951 或 Vlad 标靶）。程序自动找出可用的方块边缘，用斜边法测量扫描仪横向、竖向的 MTF，按 lp/mm 保存为扫描仪锐化配置，一次测量适用于所有 dpi。
  - **标靶文件**：本程序的 48-bit 扫描视为线性数据，其他软件的文件按 Gamma 2.2 线性化。
  - **锐化方式**：在负片转换之前，于线性扫描数据上做反卷积（Wiener），提高细节反差，同时抑制光学极限以上的噪声。
  - **默认值**：正式扫描的画面默认温和强度（40%），导入的图像默认关闭；调整面板「锐化」可逐张调整，推到 0 关闭。
  - **作用范围**：单张视图、放大镜、导出和接触表都会使用。
  - **本机实测**（V850，6400 dpi，Vlad 标靶）：横向约 2240 ppi，竖向约 1720 ppi，由 8 条竖直边缘、7 条水平边缘测得。默认强度下，横向 MTF50 从 17.5 提高到 31.6 lp/mm，竖向从 14.4 提高到 25.4，噪声增加约 19%。整张 6400 dpi 图像锐化约 1.5 秒。

## 0.4.0 真正的 RGB 48-bit 采集（实验）

打开 `Epson-Scan-plus-v0.4.0/Epson Scan plus.app`，或解压 `Epson-Scan-plus-0.4.0-macOS-arm64.zip`。适用于 Apple Silicon Mac、macOS 14 及以上，实验接口只启用 USB `04b8:0151` 的 V800/V850。本机实测识别为 GT-X980。

1. 退出 Epson Scan 2、图像捕捉及其他扫描程序，打开新版。检测成功后左侧显示「48-bit RGB」与「epson2 · 48-bit 实验接口」。
2. **先重新预览**。新接口的采集坐标与输入编码独立记录，不能直接沿用 ICA 工程的预览进行扫描。新预览会建立新工程，旧工程与原图不覆盖。
3. 选择 dpi，先用扫描菜单的「扫描当前画面」试一张，再批量扫描。仍保留单张自动进入、左右键浏览、勾选/全选/全不选、裁切与片基微调、批次进度。
4. 原始 TIFF 为不反相的 RGB16/通道，关闭扫描仪 CCT 色彩校正，设置三通道恒等 Gamma 表；本程序新工程使用输入 Gamma 1.0。原件偏暗是线性编码的正常表现，不是已转正成片。
5. 转正导出可选 TIFF 16-bit/通道或 JPEG。将这里的原始 TIFF 再作为普通图片单独导入时，也请确认「输入设置」Gamma 为 1.0；普通导入不会猜测文件是否线性。

预览也采集 48-bit，显示缩略图仍是屏幕预览。正式扫描的像素按驱动实际对齐范围记录，避免用名义玻璃尺寸拉伸预览坐标；对齐的少量外围像素只在原件保留，导出按用户裁切。进度由读取到的图像字节推动，TIFF 保存并成功返回才计为完成，不是剩余时间估算。

**实验接口的取消不是立刻让机械运动停止。** 本机中途发送停止命令后曾出现 USB 不响应，因此改为读取完当前传输、等待本张扫描结束后停止，不保存该张，也不启动下一张。界面会保持「正在取消」，完成后才解锁。扫描中退出程序也会通知独立采集进程执行这一步，归位前不要打开另一扫描程序。若扫描仪已经报错或断线，可能仍需要关机再开机。

目前属于**本机验证的实验接口**，不等同于 Epson 官方「High」品质模式；没有 ICE、红外或软件除尘，也没有 IT8 标定。高于 8-bit 的实际像素取值验证可以排除简单扩位，但不能证明传感器拥有 16 位有效动态范围。原始文件的线性 RGB 编码标记不是扫描仪专用 ICC。2400 dpi 的一张 RGB48 原件通常约为同尺寸 RGB24 的两倍数据量。

0.3.3 稳定版仍在独立目录。开发诊断时可使用本版可执行文件的 `--ica` 参数启动旧 ICA 接口；不会静默降级或把 24-bit 采集标成 48-bit。请勿同时运行两种接口。

本版包含的 SANE、libusb 许可证、对应源代码与 helper 源码位于应用包 `Contents/Resources/Scanner` 内；源码包另含可复现构建脚本。详见 `ThirdParty/README.md`。
