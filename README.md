## 功能

- **三个模块和本地库**：顶栏中间的分段按钮在 ① 采集（V850 扫描、A7R IV 翻拍；导入文件用工具栏的「导入」或 ⌘O）、② 去色罩、③ 去漏光之间切换。扫描、翻拍和导入的每一卷都自动放进库里；库是一个档案柜，每卷是一页底片保存页，打开过的卷显示正片，其余显示负片原样。见下文[库](#库)。
- **A7R IV 联机翻拍**：通过 Sony Camera Remote SDK 拍摄，实时取景和对焦检查，读出无压缩 RAW；RGB 光源翻拍时先去串色、再除以平场；像素位移（4 张或 16 张，App 从电脑把相机设好）一次快门收成一组，合成一张再转换。见下文[构建](#构建)里的 SDK 说明。
- **48-bit 采集**：内置独立的 SANE epson2 采集进程，绕过 ICA 驱动的 24-bit 限制；线性 RGB16，扫描仪不做除尘、锐化或自动调色。见[扫描仪接口](doc/scanner.md)。
- **整幅预览**：600 dpi（约 80 秒）或 150 dpi（约 50 秒），自动识别 135 和 120 画面，可手动调整或补画。
- **去色罩**：扫描值 → 片基相对密度 → 各通道斜率 → 白平衡与色阶 → 手动调整 → sRGB。斜率依次取本机标定预设、整卷自动估计、Kodak 数据表。见[胶片配置、转换与颜色](doc/film-and-color.md)。
- **调整**：片基微调、白平衡（含阴影冷暖）、色阶、曝光、对比度、高光、压高光、阴影、饱和度、色彩降噪、柔和的暗部和高光、RGB 与单通道曲线，以及按实测 MTF 的锐化。每张单独保存，可同步旋转和镜像到整卷；所有编辑都能撤销和重做。
- **除尘**：在负片上找灰尘、毛发和纤维，用周围的胶片补上，颗粒从附近一块干净的胶片借来，补的地方只减不增密度。补在去色罩之前，改调色不用重做。单张上用圆圈标出，点一下就留下或去掉，也可以手动点。只用于 16 位的负片（扫描、翻拍）。见[除尘](doc/negative-conversion.md#除尘)。
- **接触表与看片镜**：接触表放在 Metal 渲染的铝框灯箱上；Pentax 式 5.5×、Mamiya 式 4×、Peak 式 8×（135），Rodenstock 式 3×（6×6），或看局部的 Schneider-Kreuznach 式 10× 看片镜放在画面上放大细看，接触表和单张视图都能用。接触表图片可按预览直接导出，或先以 1200 dpi 扫描再导出。
- **去漏光**：第三个模块，移植自 FilmLightLab 1.5.0 的修订 9 匹配算法。用同一张照片的干净参考图（图像模型生成或自己导入）在本机修复红色 / 品红漏光，参考图只指导平滑的色彩校正，输出像素都来自原片；本卷的照片按当前调色直接处理，不用先导出。见下文[去漏光](#去漏光)。
- **导出**：TIFF 16 / 8-bit、PNG 16-bit、JPEG；sRGB、Display P3、Adobe RGB 或 ProPhoto RGB，嵌入 ICC 配置文件；写入胶片、片号、扫描仪和扫描日期等元数据，文件名可按模板生成。扫完的正片自动导出到工程的 `Exports`，未反相的原始负片保留在 `Originals`。

## 系统要求

- Apple Silicon Mac，macOS 26 或更新。
- 扫描：Epson Perfection V800 / V850（USB `04b8:0151`，实测设备名 GT-X980）。
- 翻拍（可选）：Sony A7R IV，USB 连接；构建时要有 Sony Camera Remote SDK，见[构建](#构建)。
- App 为本地临时签名，未经 Apple 公证。

## 安装与更新

- **安装**：打开 `Epson-Scan-plus-<版本>.dmg`，把 Epson Scan plus 拖到旁边的「应用程序」。如果直接在磁盘映像里打开 App，它会问要不要拷过去。
- **自动更新**：放在「应用程序」里的那一份，打开几秒后和之后每六小时看一次更新列表。有新版本就下载，核对签名，退出时换上。底栏右端会提示，点开能看改了什么，也能现在更新。
- **手动更新**：App 菜单里的「检查更新…」可以立刻看一次，也可以关掉自动下载。
- **旧版本**：换下来的放在 `~/Library/Application Support/epscan/旧版/`，留最近五个。
- **更新列表**：默认是这台 Mac 上的发布目录，不联网，见[构建与测试](doc/building-and-testing.md#发布和更新)。
- **不更新的副本**：试用版和别处的副本不自动更新。

## 快速开始

1. 退出 Epson Scan 2、图像捕捉等占用扫描仪的程序，打开 Epson Scan plus。左上角指示灯变绿、① 采集 · V850 的左栏显示「48-bit RGB」即为就绪。
2. 在 ① 采集 · V850 的左栏选择正式扫描分辨率（默认 2400 dpi）和预览分辨率，点「预览」。
3. 预览完成后程序自动识别画面，画框依次落到接触表上，第一张选中；点一下画面进入单张。检查画框，必要时用裁切工具调整，或回到接触表用画框工具补画。
4. 到 ② 去色罩，在检查器最上面的「胶片名」输入胶片名称（如 Portra 160），回车。已有本机标定的「· V850」预设时自动选用，没有时按整卷自动估计。
5. 调整画面后，回到 ①，用「扫描所选」扫描勾选的画面；扫完的正片自动导出到工程的 `Exports`。
6. 需要时在 ② 工具栏的「导出」菜单里导出接触表。

## 库

![库：每卷一页底片保存页](doc/images/library.jpg)

点顶栏的「库」或按 ⇧⌘L 打开。库是一个档案柜，每卷是一页底片保存页：

- **标签**：顶上的纸标签写卷名（没起名时写开始的时间）、胶片、张数、全分辨率的张数和已导出的张数。
- **索引签**：右上角的索引签表示来源：扫描、翻拍或导入。旧版图库里的卷注明「旧版」。
- **画面**：透明袋里每条六格。打开过的卷显示 App 渲染的正片；其余的显示负片原样，带橙色色罩。竖放的画面横过来放，和灯箱上一样。
- **同一批底片叠成一摞**：同一卷胶片扫了几次（张数一样，前三张一样），这几卷叠在一起，只露最新的一卷，索引签上写着一共几卷，下面露出几页的边。右键「摊开同一批底片的 N 卷」单独看它们，页眉的「‹」回到整个库；「…」菜单里可以关掉叠放。判断用每卷前三张的差值哈希（画面缩成 9 × 8 的灰度，比较相邻两格的明暗），正片和负片也认得出是同一张；要三张都几乎一样才算同一批。
- **操作**：双击一页打开这一卷，进入 ② 去色罩。可以按卷名、胶片、备注搜索，按来源筛选。右键可以重命名（写进那一卷的工程，留空回到开始的时间）或在 Finder 中显示；「…」菜单里能从文件打开工程，或更改新卷的存放位置。

库直接读图库文件夹里的各卷，不在里面另写索引或别的文件。用默认图库时，0.4.8 及以前的 `~/Pictures/Film Desk/` 里的卷也会列出来。正片缩略图存在 `~/Library/Caches/local.epscan.mac/Rolls/`，删了不影响工程，下次打开那一卷时会重新生成。

## 去漏光

![去漏光页：本卷第 16 张，按它在 ② 的调色打开](doc/images/leak-page.jpg)

顶栏切到「去漏光」。这一页移植自 FilmLightLab 1.5.0（修订 9），算法逐项改写为 Swift：同样的输入下，场景判断、自动保护、对齐、拟合出的模型和输出像素与原版一致，见[去漏光](doc/light-leak.md)。

1. **选照片**：在「去色罩」里选中一张，点工具栏的「去漏光」（或「画面 > 在去漏光里打开」⌥⌘L、胶片条右键菜单）直接进来；在这一页下方胶片条点一张本卷的照片也行，按它当前的调色在本机转换为 Adobe RGB 16 位正片处理，不用先导出再导入；也可以「导入正片」其他软件已去色罩、反相的 TIFF / PNG / JPEG（推荐带 ICC 的 16 位 TIFF，原文件不改动）。左右旋转在画面右上角。
2. **开始去漏光**：已有参考图时在本地免费修复；没有参考图、但标了局部区域时，只校正这些区域，也不调用 API；两样都没有时先生成参考图。也可以在「参考图」里导入在别处得到的同一张照片的干净版本，比如用你自己订阅的图像模型做的：展开「用自己订阅的图像模型做」，「导出缩图…」存下和 API 上传的一样的缩图并复制提示词，在 ChatGPT 等能改图的应用里上传、粘贴，下载结果后「导入已有参考图…」，这样不用 API Key。导入正片、API 管理和导出都在顶栏，右栏不再重复。
3. **检查**：拖动画面下方的对比滑杆看修复前后，按住「按住看原片」临时看原片，「结果 / 参考图」切换看参考图。场景（自动 / 白天 / 夜晚）、「保留灯光红晕和真实红色物体」、去偏色强度和基础调整（曝光、冷暖、绿 / 品红、对比度）随时可改，换场景或旋转后用已有参考图在本地重新拟合。所有改动都能 ⌘Z 撤销。
4. **局部处理**（可选）：「局部区域与保护」默认收起，用它的工具时保持展开。里面可以画椭圆框住漏光并点干净参考点（方式有去色偏、减雾，以及「按比例去色偏」：整片按同一个比例去掉色偏，跨过不同物体也不染色，适合翻拍灯往四周加重的颜色暗角）、用画笔保护真实的红色物体和灯光、自动检测候选区域（勾选才生效）、在自动对齐不确定时手动标对应点、裁切，以及保存 / 载入预设（与 FilmLightLab 的预设文件通用）。
5. **导出 16 位 TIFF**：原图裁切尺寸的 RGB 16 位 Adobe RGB TIFF，旁边附同一像素的 sRGB JPEG 和参数记录（`.tif.json`）；只写你选的文件，同名的 JPEG 已存在时加编号，不覆盖。本卷照片导出时按建立任务时的调色重新转换全分辨率；调色改过后，「照片」一节会提示并可「按当前调色重新载入」。

**参考图与费用**：生成参考图调用 OpenAI 图像接口（`https://api.openai.com/v1/images/edits`，模型 gpt-image-2.5-sunburst / flare 或 gpt-image-2，提示词与 FilmLightLab 相同）。只在你在确认窗口点「生成并去漏光（调用 API）」后，上传最长边 1536 px、无 EXIF 的 JPEG 缩图及附加要求；原尺寸照片留在本机。每次 1 张，不自动重试，失败或超时仍可能已计费。生成的参考图先保存再拟合，拟合失败也不会再次收费。

**API Key**：在「API 管理」里填写，可选存入 macOS 钥匙串（本 App 自己的一项，下次自动读取），否则只在本次内存中；不写入文件、任务、日志，也不会回显。不要把 Key 发到聊天中。首次或 App 更新后 macOS 可能请求钥匙串授权。

**任务**保存在 `~/Library/Application Support/epscan/LightLeak/`（每张一个文件夹：正片预览、参考图、参数），不写入照片库；本卷照片只有在开始去漏光或导入参考图后才保存任务。顶栏「历史任务」列出以前的任务，也可在 Finder 中打开这个文件夹。

## AI 助手（MCP）

Epson Scan plus 可以作为 [MCP](https://modelcontextprotocol.io) 服务器，让 Claude 等 AI 助手帮你看转换：读取选中画面的片基与来源、胶片的通道斜率、整卷估计、白平衡、色阶、负片密度和正片的直方图、白点以上的高光和 SDR 范围，画面的裁切、拉直、去串色和手动取过的点，转换实际用的斜率和来源、自动分析定出的两端，高光、阴影和整卷同一白平衡 / 色阶，每个预设的说明和在哪些卷里用，以及图库里的各卷；看预览、在画面上取点，并调整片基、中性灰、冷暖、曝光、色阶等。每次调整都是 App 里的一步编辑，可以用 ⌘Z 撤销；助手不能扫描、删除或导出文件。

1. 点工具栏中间的「AI 助手」，打开「允许 AI 助手读取和调整转换」（默认关闭）。
2. 连接助手：
   - **Claude Desktop**：点「Claude Desktop 配置」复制，在 Claude Desktop 的设置 → 开发者 → 编辑配置里加入 `mcpServers`，重启 Claude Desktop。
   - **Claude Code**：点「Claude Code 命令」复制，在终端运行。
3. 在对话里让助手「看看这张为什么偏色」之类即可。App 没开或没开启 MCP 时，助手会收到提示。

**让助手做翻拍标定**：说「帮这卷做翻拍标定」。
- **它怎么做**：先看几张预览，按物体挑出本来就中性的东西，比如拍在胶片上的色卡灰块、白牌子、白墙、灰水泥、云。从亮到暗挑 3–6 个，用 `calibration_add_points` 交给 App。
- **它怎么查**：看每个点偏离拟合多少。有点偏离 0.03 D 以上时，报告给出彼此落在一条线上的最大一组，组外的点去掉。有两组各自一致、斜率却不同时，报告点名分歧在哪几个点，不替你猜，请助手在同样的光下再加点。
- **最后**：生成「胶片 · 翻拍 · 开拍时间」预设，并告诉你选了哪些地方。App 在那几张画面上标出这些点，「翻拍预设标定」里列出它们在哪几张。
- **试过的效果**（R22）：
  - **怎么试的**：只看 App 的预览，按物体挑点。7484 的白墙、7483 阳光下的水泥地、7479 的白石块留下了。7485 阴影里的柱子、7478 的人行道、7488 的柏油路和 7478 刷漆的灰铁箱偏离太大，按提示去掉。
  - **独立检验**：生成的预设用在没取点的几张上，和 C1 的色差 7478 从 7.9 降到 3.6，7493 从 8.0 降到 4.1，中性处的偏蓝（b* −13）回到 0 附近。7491 仍然变差（5.4 → 7.0），和其他标定一样，原因还没查清。
- **注意**：
  - 判断靠认出是什么东西，不靠颜色，所以预览整体偏色也不影响。
  - 取点用浮点读数，密的地方也不会因为 8 位量化而不准。
  - 看预览时，画面会发给助手所在的 AI 服务处理。

助手启动的是 App 自己（`EpsonScanPlus --mcp`），它通过只有你的账户能访问的本机连接与正在运行的 App 通信，不经过网络。工具列表：`get_state`、`list_frames`、`list_presets`、`list_rolls`、`select_frame`、`preview`、`sample`、`adjust`、`pick_film_base`、`auto_film_base`、`pick_neutral`、`pick_highlight`、`choose_preset`、`apply_to_roll`、`reset_adjustments`、`undo`、`auto_crop`，以及预设标定的 `calibration_add_points`、`calibration_state`、`calibration_remove_point`、`calibration_clear`、`calibration_make_preset`。

去漏光页也在同一个 MCP 服务器里。FilmLightLab 原来本机 HTTP 接口能做的，这里都能做，对照表见 [去漏光](doc/light-leak.md#通过-mcp)：

- **打开和导入**：`leak_open`（本卷某张或某个任务）、`leak_import`（给出路径导入正片，原文件不改）、`leak_import_reference`（导入别处做好的干净参考图，免费）。
- **查看**：`leak_get_state`、`leak_list_jobs`、`leak_list_regions`、`leak_preview`、`leak_sample`。
- **修复**：`leak_start`（有参考图按参考图，没有时按启用的局部区域）、`leak_set`、`leak_clear_correction`。
- **用自己的图像模型做参考图**：`leak_reference_prompt`（只读，给出和 API 一样的提示词和步骤）、`leak_export_upload`（只打开保存缩图的窗口）。
- **局部**：`leak_detect`、`leak_add_region`、`leak_update_region`、`leak_delete_region`、`leak_add_protection`。
- **对齐、方向和预设**：`leak_set_landmarks`、`leak_rotate`、`leak_crop`、`leak_load_preset`。

有几件事留给你在 App 里确认：

- **生成参考图**：要上传缩图并计费，`leak_request_reference` 只打开确认窗口，可以预填质量和附加要求。
- **写文件**：`leak_export`、`leak_save_preset` 只打开保存窗口，由你选位置。
- **API Key**：助手读不到，也改不了。

## 工程文件

每次预览或导入都会在存储位置（默认 `~/Pictures/epscan/`；0.4.8 及以前默认 `~/Pictures/Film Desk/`，那里的旧工程原样保留，可用「打开工程」打开）新建一个「日期_编号」文件夹：

- `overview.tif`：整幅预览，不压缩（0.4.6 及以前为 `overview.png`）。
- `Originals/`：未反相、保留橙色色罩的原始负片，TIFF 16-bit 线性，用于存档和重新转换。
- `Exports/`：自动导出的正片，每张附带转换参数 JSON。
- `Session.epscan`：自动保存的工程，也记着卷名和备注（没填时不写）。0.4.8 及以前的工程叫 `Session.filmdesk`，照样能打开，并存回原文件。

整个文件夹可以搬移或改名：工程同时按相对路径记录文件，打开时按文件夹的新位置读取（0.4.8 起；更早的工程搬移后也会按文件名找回）。

## 构建

```sh
bash build.sh
"../Epson Scan plus.app/Contents/MacOS/EpsonScanPlus" --self-test --test-output /tmp/EpsonScanPlus-tests
```

- **工具**：只需 Xcode Command Line Tools，不需要 Metal 工具链（图像内核在 App 运行时编译），也不依赖第三方 Swift 包。
- **液态玻璃**：用 Xcode（macOS 26 SDK）构建时，用的是 SwiftUI 的液态玻璃：会流动、会融合、按下会回弹；用 Command Line Tools 构建的是运行时取用的静态玻璃。
- **翻拍要用 Sony Camera Remote SDK**：它不在这个仓库里，受 Sony 的许可约束。
  - 头文件放在 `../Sony-CrSDK/include`，`libCr_Core.dylib` 和 `CrAdapter/` 放在 `../Sony-CrSDK/lib`，或者用 `EPSON_SCAN_PLUS_CRSDK` 指定位置。
  - 构建时它会编进相机进程，SDK 的库放进 App 的 `Contents/Frameworks`。
  - 没有 SDK 时照常构建，只是翻拍面板会提示缺少 SDK。
- **图标**：源文件是 `Icon/AppIcon.icon`，编译好的图标已经提交，构建时不需要 Xcode；改图标见[构建与测试](doc/building-and-testing.md#图标)。
- **更多**：自检、扫描仪实测和命令行导出见[构建与测试](doc/building-and-testing.md)。
